# 地震台站数据质量检测服务

纯后端 Node.js + TypeScript + Fastify 服务，面向地震台站观测数据接入与质量检测。

## 能力

- 台站档案管理（建档、资料更新、状态事件审计）
- 观测摘要批量接入
- 采样完整性、波形削顶、时间同步检测
- 质量评分与问题标签
- 按台站/分数查询观测记录
- 生成时间窗口质量报告

## 启动

```bash
npm install
npm run dev
```

默认端口：`4301`。当前使用内存存储，后续可替换 PostgreSQL/时序数据库，并接入 Kafka、SeedLink 或对象存储。

## 台站资料更新

`PATCH /api/stations/:id` 由值守人员修正台站档案，可更新字段：

- `name`、`region`、`elevationM`：直接更新
- `status`：运行状态变更必须提供 `reason`，并符合状态转换规则；可附 `operator` 标识操作人
- 请求体不含任何待更新字段时返回 `400`，台站不存在返回 `404`

成功返回 `{ station, event }`，其中 `event` 为本次人工状态变更记录（仅资料字段修改、状态未变时为 `null`）。

## 运行状态转换规则

| 当前状态 | 人工可转换至 | 说明 |
| --- | --- | --- |
| `online` | `maintenance`、`offline` | 计划检修或停运下线 |
| `maintenance` | `online`、`offline` | 检修完成恢复观测，或检修后停运 |
| `offline` | `maintenance` | 重新启用须先维护检查，禁止离线直接上线 |

不允许的转换返回 `409` 并给出当前状态允许的目标列表。

## 人工状态变更 vs 观测事件

两类事件统一写入状态事件表（`GET /api/stations/:id/events` 查询），通过 `source` 区分：

- `manual`：值守人员通过更新接口发起的状态变更，记录操作人、原因、变更前后状态
- `observation`：观测数据到达时产生。观测事件**不改变**人工设定的运行状态，仅更新 `lastSeenAt`
  - 台站为 `maintenance` 时：观测照常入库，打标 `维护期间收到观测数据` 并扣分
  - 台站为 `offline` 时：观测照常入库，打标 `离线台站收到观测数据` 并扣分
  - 台站为 `online` 时：正常入库，不产生状态事件

## 一致性约定

- 档案：更新立即生效，建档与每次人工状态变更均留痕（建档事件 `fromStatus` 为 `null`）
- 接入：观测始终保留，但其评分与标签遵循台站当前运行状态，且绝不覆写人工状态
- 报告：质量报告生成时快照 `stationStatus`，非在线期间接入的数据标签自动进入报告 `issues` 与 `averageScore`
